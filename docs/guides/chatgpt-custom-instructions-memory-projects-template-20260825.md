## 先给结论：三种设置解决的是三个不同问题

| 功能 | 你可以把它理解成 | 适合保存什么 | 不适合保存什么 |
| --- | --- | --- | --- |
| Custom Instructions | 全局回答偏好 | 语言、格式、受众、语气、核验习惯 | 密码、一次性任务、机密资料 |
| Memory | 可能被系统记住的个人偏好或事实 | 稳定且必要的偏好 | 需要严格保密或经常变化的信息 |
| Projects | 某个项目的局部工作空间 | 项目指令、相关文件、术语和上下文 | 与项目无关的全局规则 |

不要用一个功能承载所有内容。全局风格放在自定义指令，长期个人偏好按账号设置管理，某个研究或代码项目的资料放在 Projects；这样更容易控制范围，也更容易在结果异常时找到是哪一层设置造成影响。

## ChatGPT自定义指令在哪里设置

官方界面可能随网页、应用版本和账号逐步调整，常见路径是：登录 `chatgpt.com`，打开账号菜单或设置，查找 Custom Instructions、个性化或类似名称，再分别填写“希望 ChatGPT 了解什么”和“希望如何回答”等字段。

设置时建议先写 5 到 8 条稳定规则，保存后用一个新对话测试。不要一次填入很长的业务手册，否则出现回答偏差时很难判断是哪条规则起作用。修改前保留一份本地副本，尤其是涉及工作流程时。

### 一套稳妥的中文自定义指令结构

```text
关于我：
- 我主要使用简体中文。
- 我的读者是没有专业背景的普通用户。
- 涉及时间、价格、型号和政策时，请提示我核对最新官方来源。

回答方式：
- 先给直接结论，再给步骤和必要解释。
- 使用短段落、表格或编号清单，避免空泛口号。
- 不确定的信息明确标注，不要编造来源或数字。
- 需要我做决定时，列出选项、适用场景和风险。
```

这类内容描述的是“如何回答”，不是“替我完成某个具体任务”。越稳定、越可验证的规则，越适合放入长期设置。

## Custom Instructions、Memory和Projects的实际区别

### 自定义指令：控制整体风格

适合规定语言、受众、输出结构和核验习惯。例如让回答默认使用中文、先给结论、对不确定事实加注释。它不应该存放每个项目的全部材料，也不应该成为密码保险箱。

### Memory：管理被记住的偏好

Memory 涉及账号可能记住或调用的信息。不同账号和版本的控制项可能不同，应该在当前设置中查看、删除或关闭。不要把“关闭记忆”理解为删除所有历史对话，也不要把聊天记录、项目文件和记忆当成一份数据。

### Projects：隔离一个工作主题

Projects 更适合论文、产品、客户项目或代码仓库等局部任务。可以把项目规则、术语、参考文件和输出格式写在一起，减少每次重复粘贴。但上传文件前仍要脱敏，并确认自己有权处理这些内容。

## 三个可直接改写的中文模板

### 写作模板

```text
请用简体中文回答。先给三句以内的结论，再给结构化正文。
面向普通读者，避免夸张营销词和无法核验的绝对表述。
涉及事实、日期、价格和官方功能时，区分已确认、待核对和推测。
最后列出需要人工检查的 3 个位置。
```

### 学习模板

```text
我正在学习【主题】，当前水平是【初学/有基础】。
请先用简单例子解释，再给一个小练习和答案思路。
不要跳过关键定义；如果我的问题有误，请先指出误解再继续。
每个结论都给出我可以自行复核的依据或检查方法。
```

### 编程模板

```text
请先复述目标、运行环境和已知限制，再提出方案。
输出代码时说明修改的文件、依赖、输入输出和测试命令。
不要猜测不存在的 API；不确定时标记并给出核验路径。
涉及密钥、用户数据或破坏性命令时，先提醒风险并使用占位符。
```

模板的作用是减少重复沟通，不是让模型自动拥有你的业务知识。具体任务仍然要提供当前背景、输入材料和验收标准。

## 冲突设置怎么排查

如果你发现 ChatGPT 没有遵守规则，不要立刻添加更多指令。按以下顺序排查：

1. 新开一个对话，排除旧对话上下文影响。
2. 检查当前是否在某个 Project 中，项目指令可能改变输出范围。
3. 暂时删掉一半自定义指令，用最小版本测试。
4. 检查 Memory 中是否保存了相反的偏好或过时事实。
5. 在提示词中明确写出本次任务的优先要求和输出格式。

如果只是想完成一次任务，不要为了它修改全局自定义指令。一次性要求应该留在当前对话，避免影响后续所有回答。

## 真实场景案例：同一用户的写作项目和代码项目

小林希望 ChatGPT 平时用中文、回答先给结论；同时，他有一个英文论文项目和一个 Python 代码项目。正确做法是把“中文、结构化、标注不确定信息”放入全局自定义指令，把论文术语和引用格式放入论文 Project，把运行环境、测试命令和代码目录放入代码 Project。

如果把三个项目的全部规则都写进全局设置，模型可能在写代码时输出论文式结构，在论文中带入代码项目术语。按范围拆分后，每个任务更容易复核，也更容易在不需要时关闭或修改局部规则。

## 错误与避坑清单

- 把密码、API Key、客户资料写入自定义指令或 Memory；
- 用一次性任务覆盖全局设置；
- 认为关闭Memory会删除所有聊天记录；
- 把 Projects 中的文件当成任何对话都能安全访问；
- 复制网上“万能指令”却不检查其中的隐私和事实要求；
- 发现回答偏差就无限增加规则，不先做最小化测试；
- 把第三方平台的“记忆”功能当成官方 Memory 同步。

## 常见问题

### 自定义指令和Memory有什么区别？

自定义指令是你主动设置的回答偏好，Memory可能管理账号记住的信息，入口和控制方式不同。

### Projects会覆盖全局指令吗？

不能一概而论。项目有自己的上下文和规则，遇到冲突时应在当前项目中明确优先级并用新对话测试。

### 自定义指令里能写隐私资料吗？

不建议。只放必要的偏好和格式规则，不放密码、Key、客户资料或长期机密。

### 关闭Memory会删除聊天记录吗？

不能这样理解。Memory、聊天历史、项目文件和临时聊天应分别查看和管理。

### 自定义指令适合写什么？

适合写语言、受众、风格、结构、事实核验和禁用表达等稳定规则。

### 第三方中文平台的指令会同步到ChatGPT吗？

不会默认同步。第三方平台有独立账号、设置和数据规则。
