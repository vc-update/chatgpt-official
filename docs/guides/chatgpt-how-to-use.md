## ChatGPT 怎么用：5 分钟完成第一次对话

### 第 1 步：从正确入口开始

如果你要使用 OpenAI 官方 ChatGPT，直接在浏览器地址栏输入 `chatgpt.com`，不要从陌生群聊、二维码、短链接或所谓“内部入口”登录。打开后检查地址栏的最终域名和 HTTPS 状态；页面标题、Logo 和搜索排名都不能证明它是官方页面。

如果你只是阅读教程，不需要在本站输入账号、密码、验证码、恢复码或 API Key。本站不会嵌入 ChatGPT 登录表单。

### 第 2 步：登录时保持方式一致

在官方登录页使用你注册账号时的原方式。登录页当前可能显示邮箱或第三方账号登录选项，具体以页面当时提供的方式为准。常见问题不是“账号突然消失”，而是这次使用了不同的登录方式，进入了另一个空账号。

登录成功后检查三件事：

1. 账号邮箱或头像是否是你预期的账号；
2. 历史对话是否出现；
3. 当前工作区、套餐和功能是否与原来的使用环境一致。

如果登录后循环跳转、验证码不通过或历史记录为空，先不要重复注册。可以先查看 [ChatGPT 官网登录与账号恢复排查](/guides/chatgpt-official-login-code-account-recovery-security-troubleshoot-20260724)，再检查浏览器 Cookie、扩展和服务状态。

### 第 3 步：新建对话时先说清任务

第一次提问不需要写得很长，但至少应该包含“要做什么、给谁用、希望怎样输出”。

```text
请帮我完成：[具体任务]
背景：[必要的上下文]
输出格式：[清单/表格/步骤/邮件/代码]
限制：[语言、长度、语气、不能做什么]
如果信息不足，请先列出需要补充的问题。
```

例如，不要只写“帮我写一篇文章”，可以写成：

```text
请帮我写一篇给中文新手看的 ChatGPT 文件上传教程。
背景：读者不知道如何准备 PDF，也担心把敏感资料上传到平台。
输出：先给 5 步操作，再列出失败排查表和安全注意事项。
限制：不要编造文件大小、额度或官方关系；不确定的地方请标注需以当前页面核对。
```

### 第 4 步：用追问把答案变成可执行结果

如果第一版答案太泛，不要重新开一个对话，直接指出需要改哪里：

```text
把上面的建议改成按优先级排列的操作清单，每一步写出成功信号和失败后的下一步。
```

```text
请检查刚才的回答：哪些内容是事实，哪些是推测？把需要我自行核验的链接、日期和数字单独列出来。
```

```text
请根据我的目标读者重写，保留结论和例子，删除空泛的形容词，不要重复同一个观点。
```

好的追问通常包含三个元素：指出原回答的问题、给出新的输出格式、说明不能牺牲的内容。只说“再详细一点”，往往只会得到更多重复段落。

### 第 5 步：核对、保存和退出

ChatGPT 的回答应当被当作工作草稿或分析助手，而不是自动可靠的事实来源。涉及日期、政策、价格、法律、医疗、金融、引用、代码和账号操作时，打开原始来源逐项核对。

重要对话可以改成容易搜索的标题、归档或导出。共享电脑和公共设备使用结束后退出账号，并清理浏览器保存的密码、下载文件和会话状态。

## 中文版、官网版和第三方平台怎么区分

“ChatGPT 中文版”不是一个看到中文界面就能确认的官方产品名称。它可能指官方 ChatGPT 使用中文回答，也可能指中文教程，或者指有独立账号体系的第三方平台。

| 使用路径 | 账号归属 | 适合什么情况 | 必须注意 |
| --- | --- | --- | --- |
| `chatgpt.com` 官方网页 | OpenAI 账号 | 原生 ChatGPT 功能、官方账号和历史记录 | 只在官方域名登录，功能以账号页面为准 |
| 官方 App 或桌面端 | OpenAI 账号 | 高频使用、移动端或系统级入口 | 从官方下载引导或可信应用商店核对主体 |
| 第三方中文工具 | 平台自己的账号 | 国内邮箱、多模型或中文工作台 | 不复用官方密码，不上传敏感资料，先看隐私规则 |

如果你的目标是官方账号、订阅、原生聊天记录或官方帮助，回到 `chatgpt.com` 和 OpenAI 官方页面；如果只是处理公开、脱敏的中文问答或需要比较不同模型，可以把第三方服务当作独立工具评估，不能把它写成官方中文版。

### 按任务选择第三方工具

以下是商业推荐，均为第三方服务，不代表 OpenAI 授权，也不是 ChatGPT 官方登录入口。使用前应自行核对服务主体、隐私政策、文件保留规则和当前功能。

| 任务 | 可了解的第三方服务 | 适合先测试什么 |
| --- | --- | --- |
| 中文问答、写作、翻译和日常办公 | [SnakeGPT](https://snakegpt.vip) | 用公开材料测试回答质量、登录方式和数据规则 |
| 多模型比较、图片和多模态任务 | [GPTCat](https://gptcat.cc) | 用脱敏提示词比较不同模型与图片工作流 |
| Codex、代码和长任务 | [ZeoGPT](https://www.zeogpt.com/register?ref=MRNWDKC3) | 用非敏感代码片段检查模型、项目和导出流程 |

这些链接带有推广关系，服务名称、模型、额度和可用性以第三方当前页面为准。不要把 OpenAI 密码、验证码、恢复码、API Key、客户资料或未公开代码交给任何不必要的服务。

## ChatGPT 怎么提问：四种常用模板

### 写作和改写

```text
请作为中文编辑，帮我把下面内容改写成给[目标读者]看的[文章/邮件/说明]。
目标：[希望读者完成什么]
语气：[专业/简洁/口语化]
必须保留：[事实、数字、术语]
输出：先给修改建议，再给完整版本。
原文：[粘贴内容]
```

### 学习和解释

```text
请把[概念]讲给[我的水平]的人听。
请按“先给结论、再解释原理、举一个例子、给三道自测题”的顺序回答。
如果存在容易混淆的概念，请单独列出区别。
```

### 办公和资料整理

```text
请根据下面的会议记录整理：
1. 已确定事项；
2. 待办事项、负责人和截止时间；
3. 尚未解决的问题；
4. 需要向客户确认的内容。
没有出现在原文中的事实不要补写，缺失信息标记为“待确认”。
```

### 编程和报错排查

```text
技术栈：[语言、框架、运行环境]
目标行为：[应该发生什么]
实际结果：[实际发生什么]
错误日志：[完整日志，先删除密钥]
已尝试：[已经做过的修改]
请先解释最可能的原因，再给最小修改、验证命令和回滚方法。
```

编程场景不要直接粘贴 API Key、Cookie、数据库密码、客户数据或私有仓库内容。让模型给出删除、迁移、支付和权限代码时，必须先在测试环境验证。

## 文件、图片和长内容怎么用

上传文件前先做一轮脱敏：删除身份证号、手机号、客户名单、合同中的隐私字段、访问令牌、API Key 和未公开财务数据。然后在提示词中写清楚处理目标，例如“提取表格中的异常行”“按章节总结并保留页码”“只检查错别字，不改动数字”。

建议按以下顺序操作：

1. 确认文件格式能被当前页面识别；
2. 先上传一份小的、脱敏后的样本；
3. 说明输出结构和需要保留的原文依据；
4. 检查模型是否确实引用了文件内容，而不是凭常识补写；
5. 下载或复制结果后回到原文件逐项复核。

如果文件上传失败，先记录页面显示的完整错误，再按“格式与大小、账号权限、当前会话、浏览器扩展、服务状态”的顺序排查，不要无休止地重复上传。生成图片时也要先明确主体、构图、文字、尺寸和禁止元素；图片生成失败或一直转圈时，参考 [ChatGPT 图片生成失败排查](/guides/chatgpt-image-generation-failed-spinner-quota-policy-20260804)。

## 怎么选择模型和工作方式

模型名称和可用选项会随产品、账号和时间变化，不建议把旧文章中的型号表当成永久规则。登录后如果页面提供模型选择器，可以按任务判断：

| 任务 | 优先考虑 | 检查点 |
| --- | --- | --- |
| 普通问答、改写和摘要 | 通用模型 | 是否准确理解上下文，是否需要引用来源 |
| 长文档和复杂分析 | 上下文或推理能力更适合的选项 | 是否能覆盖全文，是否遗漏条件 |
| 图片或多模态 | 页面当前提供的图片/视觉功能 | 是否支持当前账号、输入格式和输出方式 |
| 编程和 API | 与代码任务匹配的模型或开发工具 | 是否能运行测试，是否泄露密钥 |

“最强模型”不等于“每个任务都最好”。先用同一份公开样例测试准确性、速度、格式遵循和错误率，再决定长期工作流。

## ChatGPT 常见问题排查顺序

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 官网打不开或反复跳转 | 最终域名、浏览器 Cookie、扩展和服务状态 | 用无痕窗口或另一个浏览器重试，再看 [官网打不开排查](/guides/chatgpt-official-website-cannot-open) |
| 登录后历史记录为空 | 登录方式、邮箱和工作区 | 退出后使用原注册方式重新登录 |
| 发送按钮无反应或 Network Error | 服务状态、网络、浏览器会话和附件 | 先发一条短纯文本，再逐步恢复附件和长内容 |
| 文件上传失败 | 文件格式、大小、权限、当前会话 | 拆分文件并用脱敏样本测试，参考 [文件上传排查](/guides/chatgpt-file-upload-failed-limits-guide-20260728) |
| 回答看起来很确定但不准确 | 来源、日期、数字和上下文 | 要求列出依据，再到原始来源复核 |
| 第三方中文平台要求官方密码 | 账号边界和页面域名 | 立即停止，不提交密码、验证码或 API Key |

检查服务状态时，优先使用 [status.openai.com](https://status.openai.com/)。如果状态页正常但只有你的设备异常，通常先从浏览器、网络、扩展和登录会话查起；如果多个设备同时异常，再考虑账号或服务侧问题。

## 使用 ChatGPT 时必须核验什么

- 日期、新闻、法规、价格、产品规格和地区可用性；
- 医疗、法律、金融、税务等高风险建议；
- 论文、引用、统计数据和网页链接；
- 生产环境代码、数据库迁移、删除操作和权限逻辑；
- 任何涉及账号、支付、隐私或个人信息的结论。

对于不确定内容，可以要求 ChatGPT 输出“结论、依据、待核验项”三列，并把每个链接单独打开检查。对于文件和代码，可以要求它引用原文位置、说明假设，并给出可逆的最小修改。

## 常见问题

### ChatGPT 第一次应该怎么用？

先在 `chatgpt.com` 核对官方入口并登录，然后新建对话，写清任务、背景、输出格式和限制。第一次不要上传敏感资料，先用一条公开问题确认账号和页面工作正常。

### ChatGPT 怎么让它一直用中文回答？

在对话开头写“请始终使用简体中文回答”，并补充希望的语气和格式。若要长期固定语言偏好，可以查看当前账号是否提供自定义指令等设置，但设置名称和位置以实际页面为准。

### ChatGPT 可以直接写论文或报告吗？

可以辅助拆题、列提纲、整理材料和润色，但不应把未经核验的引用、数据和结论直接提交。学术写作还要遵守学校、期刊或机构的使用规定。

### ChatGPT 写代码可靠吗？

它适合解释报错、生成样例、补测试和比较方案，但代码必须在自己的测试环境运行。涉及权限、支付、数据删除和密钥处理时，先做人工审查和回滚准备。

### ChatGPT 上传文件安全吗？

不要默认任何在线服务适合处理敏感文件。上传前删除个人信息、密钥、客户资料和未公开内容，并查看当前产品和账号的文件保留、训练和删除说明。重要文件优先使用符合组织要求的工具。

### ChatGPT 官网和 ChatGPT 中文版是同一个东西吗？

如果“中文版”只是官方页面用中文显示或用中文回答，仍然是同一个 ChatGPT 产品；如果它是另一个网站并使用独立账号，通常属于第三方服务，不是 OpenAI 官方中文版。判断时看最终域名、账号体系和隐私规则。

### 为什么 ChatGPT 回答很长但没有解决问题？

通常是任务、受众或输出格式不清楚。让它先列出假设和缺失信息，再要求按步骤、表格或检查清单输出，并给出成功标准。不要只要求“写得更详细”。

### 官网打不开时可以直接使用镜像站吗？

可以把第三方平台作为独立工具评估，但不要把镜像站当成官方入口，也不要在第三方站点输入 OpenAI 密码、验证码或 API Key。先看服务主体、隐私政策、数据删除和账号规则，再用脱敏内容小范围测试。
