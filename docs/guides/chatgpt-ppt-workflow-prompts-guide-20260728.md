# ChatGPT 怎么做 PPT？从大纲、逐页内容到演讲稿的完整教程【2026年7月】

更新时间：2026年7月28日

用 ChatGPT 做 PPT，最容易踩的坑是直接说“帮我生成一份 PPT”。这种提示往往会得到十几页重复的套话。**更有效的方法是把任务拆成：明确受众和结论 -> 设计故事线 -> 生成逐页内容 -> 补图表与演讲稿 -> 人工核验数据和排版。**

截至 2026 年 7 月，OpenAI 已把演示文稿列为 ChatGPT Work 可以处理的成品类型之一。但不同账号和入口的文件输出能力可能不同，因此本文同时给出“直接交付”和“先生成内容、再到 PowerPoint/WPS 排版”两条路线。

> 独立声明：本站不是 OpenAI 或 ChatGPT 官方网站。不要把 AI 生成的数字、案例、引用和结论直接用于正式汇报，发布前必须核对原始资料。

## 先选路线：直接做成品，还是先做内容？

| 路线 | 适合谁 | 优点 | 注意事项 |
| --- | --- | --- | --- |
| ChatGPT Work 直接交付 presentation | 有对应入口、任务明确的用户 | 可以围绕成品持续迭代 | 仍要检查文件、字体、图表和引用 |
| 生成大纲 + 逐页内容 | 所有用户 | 稳定、可控、容易迁移到 PowerPoint/WPS | 需要自己完成视觉排版 |
| 生成 Markdown / VBA / 脚本 | 熟悉工具或开发的用户 | 适合批量和模板化 | 运行代码前必须审查，避免宏与脚本风险 |

新手优先用第二条。先把内容结构做扎实，再考虑动画、模板和自动化。

## 第一步：把任务背景一次说清楚

至少提供以下信息：

| 信息 | 示例 |
| --- | --- |
| 汇报主题 | 2026 上半年电商投放复盘 |
| 受众 | 市场负责人和公司管理层 |
| 目的 | 解释结果、定位问题、申请下半年预算 |
| 页数 / 时长 | 12 页，15 分钟 |
| 已有资料 | 月度数据、渠道报表、用户调研 |
| 语气 | 专业、简洁、结论先行 |
| 禁止项 | 不编造数据，不使用无法核验的案例 |

可直接复制这个总提示词：

```text
你是资深商业演示顾问。请基于我提供的资料设计一份 12 页 PPT，
受众是公司管理层，汇报时长 15 分钟，目标是复盘上半年结果并提出下半年行动方案。

要求：
1. 先给一句话核心结论和完整故事线；
2. 每页只解决一个问题；
3. 每页输出：标题、核心结论、3-5 个要点、建议图表、数据来源、演讲提示；
4. 不编造我没有提供的数据；
5. 对缺失信息用“待补充”标记；
6. 最后检查重复页面、逻辑跳跃、无来源数字和过长文案。

先不要写逐页正文，先给目录和每页目的，等我确认后继续。
```

## 第二步：先审故事线，不要急着写正文

一份常见的工作汇报可以按这个顺序：

1. 结论摘要：最重要的三个发现；
2. 目标与范围：这次汇报回答什么问题；
3. 结果概览：核心指标与目标差距；
4. 关键变化：哪些渠道、地区或产品发生变化；
5. 原因分析：证据支持的主要原因；
6. 案例或用户反馈：解释数字背后的行为；
7. 方案选择：可选路径及取舍；
8. 行动计划：负责人、时间和指标；
9. 风险与资源：需要什么支持；
10. 总结：要管理层做什么决定。

检查每一页是否都有“唯一目的”。如果两页回答同一个问题，就合并；如果页面只有背景介绍、没有结论，就改成结论式标题。

## 第三步：让 ChatGPT 输出逐页表格

确认目录后，用下面的格式继续：

```text
按确认后的目录输出逐页内容，使用表格：
页码 | 结论式标题 | 本页要回答的问题 | 3-5 个要点 | 建议图表 | 数据来源 | 演讲提示

标题必须表达结论，不要只写“市场分析”“问题与挑战”这类空标题。
每个要点不超过 28 个汉字；没有来源的数据标记为“待核验”。
```

比如不要写“渠道分析”，改成“自然搜索贡献增长，但品牌词依赖仍然过高”。这样的标题即使观众只扫一眼，也能看懂核心结论。

## 第四步：把文字变成图表和页面

| 信息类型 | 优先图表 |
| --- | --- |
| 随时间变化 | 折线图、面积图 |
| 多对象比较 | 条形图、点图 |
| 构成占比 | 堆叠条形图，少量类别可用环形图 |
| 流程和步骤 | 流程图、时间线 |
| 方案取舍 | 二维矩阵、对比表 |
| 一个关键数字 | 大数字 + 简短解释 |

让 ChatGPT 给图表建议时，要求它同时说明：横轴、纵轴、单位、数据来源、要强调的结论。否则很容易出现“有图但没有信息”的装饰性页面。

配图也应服务内容。需要生成封面、示意图或场景图时，可以继续阅读 [GPT Image 2 图片生成与提示词](/guides/gpt-image-2-official-entry-api-chatgpt-images-2026-06)。

## 第五步：生成演讲稿，而不是把页面读一遍

可以这样追问：

```text
为每页生成 40-70 秒的演讲提示，不重复朗读页面文字。
每页包含：开场句、要解释的数据、与上一页的衔接、下一页过渡。
对可能被追问的数据列出 1-2 个备答。
```

演讲稿应解释“为什么重要”和“下一步是什么”，而不是把屏幕上的项目符号换一种说法。

## 四类常用 PPT 提示词

### 工作汇报

```text
把以下周报整理为 8 页管理层汇报。重点不是罗列完成事项，而是展示目标进度、关键成果、偏差原因、风险和下周决策事项。每页只保留一个结论。
```

### 项目方案

```text
为“客服知识库升级”设计 10 页项目方案，受众是业务负责人。覆盖现状、用户痛点、目标、方案架构、实施阶段、人员分工、成本假设、风险、指标和需要批准的事项。
```

### 课程课件

```text
为没有基础的大学生设计一份 45 分钟“生成式 AI 入门”课件。每 8-10 分钟安排一个练习或提问，避免只有概念定义；每页给教师讲解提示和学生互动方式。
```

### 融资或路演

```text
根据我提供的真实资料设计 12 页路演结构，覆盖问题、解决方案、产品、市场、商业模式、进展、竞争、团队、财务假设和融资用途。不得虚构客户、收入或市场数据；缺失项标记待补充。
```

## PPT 成品检查清单

### 内容

- [ ] 第一页之后能在 30 秒内说清核心结论；
- [ ] 每页只有一个明确目的；
- [ ] 所有数字都有来源、单位和时间范围；
- [ ] 没有虚构客户、案例、引用或统计数据；
- [ ] 建议与前面的证据相互对应。

### 表达

- [ ] 标题是结论，不是栏目名；
- [ ] 每页文字可以在正常字号下读清；
- [ ] 图表重点明确，没有多余装饰；
- [ ] 专有名词、日期和公司名称一致；
- [ ] 演讲稿没有重复朗读页面文字。

### 安全

- [ ] 删除身份证号、手机号、邮箱和客户姓名；
- [ ] 没有 API Key、账号密码、Cookie 或内部链接；
- [ ] 未公开财务数据符合公司使用规则；
- [ ] AI 生成图片、文字和引用已人工核验。

## 常见失败原因

### 内容很空

原因通常是没有提供原始资料和受众。解决办法不是要求“写得更详细”，而是补充真实输入、目标和必须回答的问题。

### 页面重复

先让 ChatGPT 输出每页“唯一目的”，再写逐页内容；用“这页删掉后会损失什么信息”检查是否重复。

### 数据看起来合理但查不到

明确要求只使用上传资料或提供来源链接，对缺失内容标记“待补充”。正式汇报前回到原始报表核对。

### 排版像文档，不像演示

把一页长文拆成“一个结论 + 一个证据 + 一个图表”。ChatGPT 负责信息结构，最终视觉层级仍需要在演示软件中检查。

## 常见问题

### ChatGPT 能一键生成能下载的 PPT 吗？

当前 Work 面向 presentation 等成品交付，但具体文件输出取决于入口、账号和任务。即使生成了文件，也必须检查字体、图表、数据和引用。

### 不会设计也能用 ChatGPT 做 PPT 吗？

可以。先让它完成故事线、逐页标题、要点和图表建议，再套用公司模板。不要让 AI 同时随意决定内容、品牌和视觉规范。

### 做 PPT 需要上传原始资料吗？

有真实资料会明显提高质量。上传前先脱敏，只保留完成任务需要的页面、字段和时间范围。

### 哪种模型最适合做 PPT？

不要只按模型名字判断。更重要的是长文档理解、文件上传、图表处理、图片生成和成品交付能力，以及你是否能复核结果。模型与功能会更新，以当前平台显示为准。
